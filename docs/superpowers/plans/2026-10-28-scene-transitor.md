# Scene Transitor — план реализации

Основание: итог обсуждения одобрен пользователем; разрешены план и реализация.

Работа выполняется в текущем checkout с сохранением исходных изменений MenuLifetimeScope и FillSceneState. Проверки Unity выполняются в игнорируемой копии `.utmp/scene-transitor`, с платформенными подменами только в копии. Коммиты и публикация не входят в задачу.

## Контракт

- Сценовые компоненты сохраняют GUID и живут в сценах; SceneStateMachine живёт в ProjectLifetimeScope.
- Переход — `SwitchStateAsync<TState>()`, повторный переход в текущее состояние ничего не делает. Перезапуск явный.
- Enum и ограничение class удаляются. Экземпляр загруженного состояния передаётся базовому SwitchTo.
- Сценовые компоненты объединяются в GameFSM/Scenes под сборкой MadSlime.UI: это позволяет конкретным состояниям ссылаться друг на друга без цикла Gameplay → UI → Gameplay.
- FSM отвечает за жизненный цикл, SceneTransitor — Unity-операции и время жизни загрузочного экрана, LoadingScreenPresenter — наполнение UI. Первоначальная инициализация переносится в GameStartup.
- Подписки активного состояния: Enter/Exit. Подписка presenter на прогресс подготовки имеет отдельный срок жизни до закрытия экрана.
- Exit виртуальный, OnStopped удаляется. OnDisable не повторяет Exit. Пауза не перерабатывается.
- FillExitFlow удаляется; реклама вызывается при принятом пользовательском запросе перехода, не в Exit.
- Обработка ошибок — на границах Forget; await передаёт исключение вызывающему. Очистка принадлежит явным Stop/Exit/Dispose, без вложенных catch/finally.
- Авторские логи удаляются в MadSlime, сторонние и генерируемые файлы не изменяются.

## Риски для проверки

- После отмены ожидания Unity может завершить физическую загрузку: состояние не должно входить после остановки.
- При переезде компонентов сохранить GUID, namespace, имена классов и сериализованные поля.
- При переносе подписок в Enter сохранить SessionFinished при Stop, не дать событию инициировать повторный переход.
- Подписки sceneLoaded и прогресса освобождаются при успехе и остановке владельца.
- Реклама не вызывается при повторном запросе во время перехода или общем завершении приложения.
- Существующие незакоммиченные удаления пользователя остаются удалёнными.
