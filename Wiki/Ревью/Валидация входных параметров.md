## 2. Идея: `ArgumentGuard.CheckRange` (+ `CheckPositive`, `CheckOrder`)

Диры в `ArgumentGuard` нет метода для значений — поэтому каждое место из §4.1 пишется по-старому, вручную. Предложение — добавить в семейство `Check*` (имена в стиле CheckAssigned/CheckNotNull; «low/high» — уже привычные проектные слова):

```csharp
// Диапазон: value обязано попадать в [low, high] включительно.
public static void CheckRange(float value, float low, float high, string paramName)
{
    if (value < low || value > high)
    {
        throw new ArgumentOutOfRangeException(
            paramName, $"{paramName}={value} must be between {low} and {high}.");
    }
}

// Перегрузка для целых.
public static void CheckRange(int value, int low, int high, string paramName) { ... }

// Самый частый подслучай проекта: «строго больше нуля».
public static void CheckPositive(float value, string paramName)
    => CheckRange(value, float.Epsilon, float.MaxValue, paramName);

// Пары Min/Max в конфигах: low обязано быть не больше high.
public static void CheckOrder(float low, float high, string paramName)
{
    if (low > high)
    {
        throw new ArgumentOutOfRangeException(
            paramName, $"{paramName}: {low} is above {high}.");
    }
}
```

Примеры «до → после»:
- `Wallet.Add` (Economy/Logic/Wallet.cs:30–32): `if (amount <= 0) throw ...` → `ArgumentGuard.CheckPositive(amount, nameof(amount));`
- `Rewarder` (Economy/Logic/Rewarder.cs:56–58): `if (percent < 0f || percent > 1f) throw ...` → `ArgumentGuard.CheckRange(percent, 0f, 1f, nameof(percent));`
- `TimerStateMachine` (Game/Logic/TimerStateMachine/TimerStateMachine.cs:30–32) → `CheckPositive(duration, nameof(duration));`
- `MusicChannel` (Audio/Logic/MusicChannel.cs:35–51): три блока → три `CheckPositive(...)`; пары `MinPitch/MaxPitch` в Absorber/PlayerPickupSound/AudioPlayer → `CheckOrder(config.MinPitch, config.MaxPitch, nameof(...));`
- `LevelsCatalog.OnValidate` (Levels/Data/LevelsCatalog.cs:25–27) → `CheckRange(range.FromLevel, 1, range.ToLevel, nameof(range))` + `CheckOrder(...)`.

Заметки:
- Unity-атрибут `[Range(min, max)]` в инспекторе не бросает, а тихо клампит — для ассет-конфигов правило «упасть с эксепшеном» остаётся за `OnValidate` + `CheckRange`.
- Существующие CheckAssigned/CheckNotNull принимают `object` — новый метод стоит сделать типизированным (float/int), без бокса.
- Отдельный подтип из аудита — «пустота коллекции/кривой» (`Length == 0`, `Count != ожидаемого`, §4.2): это не range, но по той же логике напрашивается парный хелпер `CheckNonEmpty`.
- Порядок миграции: сначала «чистые» параметры (Mover, Wallet, Rewarder, TimerStateMachine, MusicChannel — в §4.1 помечены «параметр»), потом Awake-инварианты конфигов и пары Min/Max.
